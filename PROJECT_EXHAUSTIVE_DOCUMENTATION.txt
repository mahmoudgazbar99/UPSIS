1. EXECUTIVE OVERVIEW & APPLICATION PURPOSE
--------------------------------------------------------------------------------

1.1 High-level purpose
The application is a campus ERP for the “École de Santé Gabès” (Higher Institute
of Nursing / health sciences, Gabès, Tunisia). It manages the student lifecycle
from bilingual (French + Arabic) enrolment, through groups, timetable, grades,
attendance, finance (tuition cap 9 800 DT), year-end promotion/archival, and
document generation (inscription / presence / success certificates as Word/PDF).

There is no public REST/GraphQL API. Almost every screen is a PHP script that:
  (a) starts a PHP session via config.php,
  (b) checks a role helper (require_admin, require_finance, …),
  (c) optionally mutates MySQL on POST,
  (d) calls page_head()/page_foot() from layout.php to wrap HTML.

Two JSON helpers exist for live polling (attestation_live.php, etudiant_inbox.php).
They require an existing cookie session; they are not a third-party API.

1.2 Primary business logic
- Enrolment: inscription.php two-step form (verify then submit). Unique CIN/
  passport, email, inscription number. Auto-assignment to Cours + one of two
  TD groups per semester of the student’s niveau (config.php
  assign_student_to_academic_groups / assign_tronc_commun_groups).
- Grades: table `note`. Composite unique (id_etudiant, id_mat, semestre).
  calculated_note() in config.php:
      if note_rattrapage is set → that value;
      else if note_cours and note_td exist:
          if volume_tp > 0 and note_tp set → 0.25*CC + 0.50*exam + 0.25*TP;
          else → 0.30*CC + 0.70*exam;
      else → legacy column `note`.
- Attendance: table `presence_etudiant`. Unique session key
  (id_groupe, id_mat, id_etudiant, date_seance). Hours default 1.50 or average
  from emploi_temps. Elimination: ≥4 absences per matière OR ≥ 10% of 444 S1
  hours (44.4 h) for the semester, unless elimination_derogation exists.
- Finance: table `finance` (each payment) + `finance_solde.total_paye` (running
  total, CHECK 0..9800). Remaining due = 9800 − total_paye. Finance dashboard
  rings on index.php for the finance role.
- Promotion: promotion.php preview then commit. Requires admin password AND
  typed confirmation “PROMOUVOIR”. Archives JSON payloads, fee rows, grades;
  resets finance_solde; increments niveau for “admis”.
- Certificates: PhpWord TemplateProcessor on templates/template_inscription_2.docx
  (inscription); PhpWord-generated DOCX for presence/success. Preview via
  CDN jszip + docx-preview. Bulk PDF uses LibreOffice (Docker) or Word COM
  (Windows convert_inscriptions_to_pdf.ps1).

1.3 User roles and permission tiers
Session key: $_SESSION['user_role'] in {admin, enseignant, finance, stage, etudiant}.

  admin
    Cookie session name: PHPSESSID (default).
    Auth: login.php POST role=admin + password_verify against admin_user.password_hash
          for username “admin” (function admin_password_hash()).
    Access: entire staff UI. Stage users cannot stay on admin pages.
    Extra: changer_mot_de_passe.php, promotion, archives, account CRUD, audit log.

  enseignant
    Auth: CIN 8 digits + password (bcrypt; legacy MD5 upgraded in-place on login).
    Table enseignant; must have active=1 (column added by ensure_teacher_active).
    Session: teacher_id. Can enter notes and presence only for affectations
    (enseignant_affectation). Dashboard shows missing grades / open presence.

  finance
    Auth: finance_user.username + bcrypt password, active=1.
    Session: finance_id + finance_auth_generation. If auth_generation in DB
    changes (password edit), session is invalidated (require_finance()).
    Access: finance.php payments, recu_paiement.php, finance dashboard rings.

  stage
    Auth: stage_user.cin + bcrypt, active=1. Table may be missing until
    stage_accounts_migration.sql; login then shows a setup error.
    Session: stage_id + stage_auth_generation. Isolated to stage_portal.php
    and logout.php (enforce_stage_route_isolation()). Portal is currently a
    placeholder (“Service des stages”).

  etudiant
    Separate cookie name ESG_STUDENT (config.php app_is_student_request()).
    Auth: connexion_etudiant.php CIN + etudiant_compte.password (bcrypt), active=1.
    Account created on creer_espace_etudiant.php if student already enrolled.
    Isolated to dashboard.php, etudiant_inbox.php, logout.php
    (enforce_student_route_isolation()). Staff sessions that hit student pages
    are not destroyed if they are not students; invalid student sessions are
    wiped by dashboard_refuse_session().

1.4 Core functional workflows (end to end)
A. Staff login → login.php → index.php dashboard (iframe modules for admin/
   teacher/finance). Menu items load *.php?embed=1 into iframe[name=dashboard-content].
B. Register student → inscription.php verify → submit → INSERT etudiant →
   assign groups → optional Word attestation.
C. Teacher grades → gestion_notes.php grid or manual form → UPSERT note → audit_record.
D. Presence sheet → presence_etudiants.php save_presence → presence_etudiant rows.
E. Student asks for presence certificate → dashboard.php POST demande_attestation
   → demande_attestation. Admin polls attestation_live.php, accepts/refuses on
   demandes_presence.php, student_notify() writes etudiant_inbox.
F. Finance records payment → finance.php create_payment → finance + finance_solde.
G. Year rollover → promotion.php commit → archives + niveau++ + solde reset.

4. SYSTEM ARCHITECTURE & DATA FLOW
--------------------------------------------------------------------------------

4.1 Client–server model
Server-side rendered multi-page app (MPA). No SPA router, no Inertia, no
WebSockets, no GraphQL. HTTP:

  Browser  --GET/POST-->  Apache  -->  PHP script  -->  PDO/MySQL
                |                         |
                +-- assets/*.css, images, CDN Bootstrap/fonts
                +-- fetch JSON (same origin, credentials: same-origin)

Dashboard modules: parent index.php hosts <iframe name="dashboard-content">.
Links use target="dashboard-content" and href="module.php?embed=1".
layout.php app_is_embedded() hides navbar; body.embedded-view CSS makes the
iframe document the scrollport (html overflow hidden, body overflow-y auto).

4.2 Request lifecycle (typical staff POST)
  1. Apache maps /webapp/finance.php to that file.
  2. finance.php require_once config.php.
  3. config.php: detect student vs staff → session_name; session_set_cookie_params
     (httponly, samesite Lax, secure if HTTPS); session_start(); strip student
     keys from staff session if mixed; define db() PDO singleton.
  4. enforce_stage_route_isolation() / enforce_student_route_isolation() may
     302 away.
  5. Page calls require_finance() → require_login() → 302 login.php if no role;
     403 if wrong role; finance_user.auth_generation check.
  6. If POST: verify_csrf() hash_equals session token vs POST csrf_token
     (419 on fail).
  7. Business SQL in a try/catch PDOException; audit_record() best-effort.
  8. layout.php page_head() emits HTML, theme classes from a blocking inline
     script reading localStorage app-theme (light|dark) and app-style
     (original|atlas|glass|macos).
  9. page_foot() Bootstrap JS + Mac OS window/command/iframe scripts.
 10. Response HTML; next navigation is a full page or iframe load.

4.3 JSON poll lifecycle
  index.php / demandes_presence.php setInterval 2000ms:
    fetch('attestation_live.php', {credentials:'same-origin', cache:'no-store'})
  attestation_live.php require_admin(); JSON count/stamp/requests.
  If stamp changes, optional iframe.attestationLiveReload(data).

  dashboard.php polls etudiant_inbox.php GET; POST id_notif + csrf marks read.

4.4 Global state
  Server: PHP $_SESSION only. Keys used:
    user_role, teacher_id, stage_id, stage_auth_generation,
    finance_id, finance_auth_generation, id_etudiant,
    csrf_token, flash{kind,message}.
  Client: localStorage app-theme, app-style. No Redux/Vuex.
  iframe postMessage is used in layout.php to sync theme into embeds.

4.5 Queues / jobs / cache
  None. No Redis, no cron PHP, no queue worker. Polling replaces push.
  Schema “migrations” are SQL files run manually (phpMyAdmin) or CREATE TABLE
  IF NOT EXISTS inside PHP (attestation_ensure_tables, presence_ensure_table,
  audit_ensure_table, ensure_etudiant_compte_table, elimination_ensure_table).

4.6 Embedding detection
  GET embed=1 OR header Sec-Fetch-Dest=iframe OR X-Requested-With=XMLHttpRequest.

7. SECURITY, AUTHENTICATION & AUTHORIZATION
--------------------------------------------------------------------------------

7.1 Authentication
  Mechanism: PHP native sessions (cookie), not JWT, not OAuth, not MFA.
  Password storage: password_hash() PASSWORD_DEFAULT (bcrypt $2y$).
  Admin hash loaded each request from admin_user.
  Teacher legacy MD5 auto-upgraded on successful login.
  session_regenerate_id(true) on all successful logins.
  Finance/stage session binding via auth_generation integer; password or
  identity change increments it → require_* destroys session.

7.2 Authorization
  Gate functions in config.php: require_login, require_admin,
  require_teacher_or_admin, require_finance, require_stage.
  Teacher data scoping: SQL joins enseignant_affectation in gestion_notes
  and presence_etudiants.
  Student isolation: separate cookie + enforce_student_route_isolation.
  Stage isolation: enforce_stage_route_isolation.

7.3 CSRF
  Token: 32 bytes bin2hex in $_SESSION['csrf_token']; html hidden field;
  verify_csrf() uses hash_equals; failure HTTP 419.
  Applied on most mutating POST pages listed in §5.17.
  NOT applied on: login.php, connexion_etudiant.php, inscription.php POST,
  emploi_temps.php?build=1 GET, certificate GET generators (read-only DOCX).
  etudiant_inbox.php POST is protected.

7.4 XSS
  Helper e() htmlspecialchars ENT_QUOTES UTF-8 with mb_check_encoding repair.
  Most echoes use e(). Some JSON embeds use JSON_HEX_TAG|AMP|APOS|QUOT.

7.5 SQL injection
  Prepared statements dominate. A few concatenations:
  student_notifications_latest LIMIT is cast int clamped 1..50 then
  concatenated (safe). Dynamic SQL in archive_export should be reviewed
  per export filters. information_schema queries use bound table names
  in db_table_exists.

7.6 CORS
  No Access-Control headers. Same-origin only. fetch uses credentials
  same-origin.

7.7 Rate limiting
  None at application layer. Apache/mod may apply globally (not configured
  in repo). Login is unbounded.

7.8 Cookie / session fixation
  regenerate_id on login. httponly. No explicit session timeout in code.

7.9 File generation
  generate_* require_admin (or teacher for feuille). CIN from GET.
  Template path is filesystem local, not user-controlled.

7.10 Secrets in repo
  Default DB password myapp_password, admin bcrypt in db_new.sql,
  finance seed hash, README plaintext passwords. Docker MYSQL_ROOT_PASSWORD=root.
  Treat as lab credentials, not production secrets.

7.11 Iframe
  Modules load same-origin embed=1. No CSP header in scanned files.
  X-Frame-Options not set (dashboard iframe would be same-origin anyway).

APPENDIX A — calculated_note() exact algorithm
--------------------------------------------------------------------------------
Input array keys: note_rattrapage, note_cours, note_td, note_tp, volume_tp, note
Returns ?float rounded to 2 decimals, or null if nothing numeric.

  if note_rattrapage !== null:
      return (float) note_rattrapage
  if note_cours === null OR note_td === null:
      return note === null ? null : (float) note
  cc = (float) note_cours
  exam = (float) note_td   // column is named note_td but used as exam
  if (float) volume_tp > 0 AND note_tp !== null:
      return round(cc*0.25 + exam*0.50 + note_tp*0.25, 2)
  return round(cc*0.30 + exam*0.70, 2)
